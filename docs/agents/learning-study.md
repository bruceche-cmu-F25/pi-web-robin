# Learning Hub weekly plan and reminders

- `extension/robin/study-plan.ts` is browser-safe: weeks are local Monday–Sunday, recurring sessions use weekday + wall-clock time, and reminder eligibility has a 30-minute catch-up window. The initial LeetCode 10:00–11:00 session runs 2026-11-03 through 2026-12-31. Completion is never inferred from opening a link.
- `study-plan-domain.ts` owns `~/.pi/robin/study-plan.json`, a learning preference/plan, not one of the 11 migrated operational runtime-state files. Week saves compare revisions so another tab's changes are not silently overwritten. Default sessions expire at the December goal; later weeks receive a fresh editable template. The API in `app/api/robin/learning/study` is only an adapter. Planner Buddy is a separate, persistent zero-tool scoped conversation at `/api/robin/learning/study/chat`. Every turn sees bounded saved and unsaved week/schedule context, recent recorded practice attempts, and this week's occupied calendar times; it can ask follow-ups and propose a plan, but cannot write to the week, reminders or calendar. Its conversation session id lives in `assistant.json`; the visible transcript is retained per browser by `AgentPanel`, which marks session rotation after inactivity/date changes. New conversation clears only Buddy's session and visible transcript.
- `calendarBoard()` projects recurring sessions as read-only `source: study` events; they are not duplicated into the local calendar or written to Google. For the default LeetCode block an existing timed appointment takes precedence, avoiding a second item and an interruption during meetings. Intentional custom sessions still display even if they conflict. Planner sees the study block as occupied time.
- `StudyReminder` is one root client owner, limited to foreground Robin pages. At event start it links to today's NeetCode/LeetCode problem when available, otherwise the saved resource. Esc snoozes; Snooze defers 10 minutes; Skip and Open dismiss this occurrence, neither records a solve. Before interrupting, the default LeetCode reminder checks for a recorded attempt and current calendar conflicts. Reminder acknowledgements and short foreground leases are per-browser localStorage, not cross-device attendance. Closed pages, locked phones and offline browser tabs receive no popup or push; this feature does not start a background scheduler. Other open dialogs take precedence. No app-wide lock.
- Learning Hub has two URL-addressable views (`/learn` and `/learn?view=planner`). **本周** puts the existing next-problem/next-course tracks first, followed by a compact weekly recap: recorded practice days are separate from manually checked milestones, whose checklist is disclosed on demand. The course outline and manually checked milestones remain collapsed; the shelf and resource rail open by default on desktop and mobile. The rail's destinations are categories, not a numbered syllabus, and include a direct external link to the current freeCodeCamp Back End Development curriculum (completion remains manual). A failed progress read hides stale tracks and offers a local retry, rather than treating a cached count as live. The saved weekly objective remains visible when the plan read fails, but its counts/checklist are hidden until a successful sync. **规划本周** gets the full content width (the resource rail is hidden): the human-edited objective/milestones and study sessions occupy the left work column, and the full Planner Buddy conversation (transcript, composer and next saved reminder) is on the right. At ≤760px, a sticky two-choice switch shows either **计划与提醒** (objective plus session editor) or **Planner Buddy** (conversation plus next saved session), instead of stacking all three into one long page. Both panes stay mounted and keep unsaved form/chat drafts and in-flight replies; adopting a proposed plan reveals and focuses the objective, and the Buddy reminder link reveals and focuses the schedule. The switch stays below the phone drawer button; the chat becomes compact after the composer first receives focus and stays that size until switching away (so the proposal button does not jump during a tap); no page-wide scroll locking. Unlike Pi Web, Robin does not mount `useViewportHeight`, so do not rely on its global `data-keyboard-open` flag here. Buddy asks and answers across turns; a valid structured plan adds a per-reply "Use in plan draft" action, but applying it only replaces the local draft, and the user must explicitly confirm it. Editing the objective or reminders does not remount the conversation. Switching views preserves unsent Buddy text and unsaved plan edits while the hub stays mounted; manual reload asks before discarding plan edits. Weekly-plan and study-session saves are separate. The reminder schedule uses responsive rows, not a single long line of fields. New weeks receive an editable template; Buddy does not run on page open. External freeCodeCamp course completion remains manual because no trusted progress integration exists.
- The accelerated Python review covers Nov 4–22 in `components/robin/python-review.ts`; `python-review-cards.ts` supplies 19 bilingual teaching cards with **only** an explanation and a code example. The week's rows are visible above the recap; other dates are disclosed on demand. Opening a card never counts as completion. The user can explicitly check or uncheck **已复习** on or after that date; future cards are preview-only. `study-plan-domain.ts` stores only the per-day check, revision and check time in `study-plan.json` via POST `/api/robin/learning/study`, separate from editable weekly milestones and LeetCode attempts. A stale-tab toggle gets 409 and can reload, without silently changing the checkbox. Old answer/attempt records, if any, remain untouched on disk but are neither returned by GET nor displayed and no new answers are accepted. The next day offers one pending catch-up card (most recent unchecked date) without shifting the schedule; missed cards remain available through late December. No code execution, automatic grading, calendar event, freeCodeCamp completion or background push. Nov 23 remains the backend V9 transition.
