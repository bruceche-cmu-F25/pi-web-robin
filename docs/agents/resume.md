# Resume workspace

- `/dashboard/jobs/resume` is the **Resume** tab within Job hunt, not a new global destination. `JobHuntWorkspace` keeps Jobs/Events client navigation; entry and exit for Resume use native links, like other editors, so `beforeunload` also protects Back. Session/cwd remain in links. Jobs/Events' in-memory filter snapshots do not survive a full-document editor round trip; browser Back still carries their original URLs.
- `extension/robin/resume-domain.ts` owns one source document in `resume.json` under `ROBIN_DATA_DIR` / `~/.pi/robin`. It is a separate document, not a task/runtime-state collection and not the scoring CV or the application PDF. GET does not create it or copy profile content. Save is explicit, byte-bounded (200 KB UTF-8), locked/atomic and revision-checked. Identical-content retries acknowledge a lost response without overwriting. Corrupt data fails closed.
- The editor is a native, non-wrapping LaTeX textarea with a synchronized line-number gutter; long lines scroll inside it rather than widening the page. Desktop keeps the editor sticky next to the agent/diff. Native Tab exits the field rather than trapping keyboard users.
- Manual `.tex` import, the template and completed agent edits change only the editor draft. The user explicitly requested **direct agent editing**: validated results now update a matching draft automatically, without an Apply button. Download includes the current draft; Save is still explicit. One-step Undo works only while the draft still equals that agent result, so it cannot erase later typing. The latest diff is kept after applying/undoing and is not a persisted version history. A new request leaves the previous diff/undo available on failure. Save failures keep drafts; conflict comparison explicitly adopts a server revision only after the user chooses it. Newer typing survives older save acknowledgements.
- `lib/text-recovery.ts` has an isolated `resume/main/source` slot. Back up at each edit, including imports and proposal application. Recovery is opt-in, never silently applied over a server read; exact acknowledgements clear only their own receipt. Browser storage is best effort, not encrypted or a server backup. Instructions, pasted JD and unapplied proposals are not backed up.
- `lib/resume-agent.ts` uses the existing scoped assistant runner: one-shot, exact **empty tool set**, shared `resume-proposal` lock, 180-second turn, abort on cancellation, no writes. A regular edit sends the current draft, instruction, optional pasted JD and optional profile CV. Employer text is not candidate evidence. Structured output must contain a complete LaTeX document or `source: null` for clarification; malformed/truncated output is never applied. The client revalidates the structured result and compares the live source ref to the request snapshot before updating it. Continued typing produces a visible, unapplied conflict; even reverting later does not auto-apply that stale result. Ask again against the current source.
- `components/robin/resume-changes.ts` uses the installed `diff` package's `structuredPatch` with two context lines, 100 ms / 2,000 edit bounds, a 10,000 input-line bound and 5,000 output-row bound. Over-budget diffs fall back to complete sources. Hunks show original/new line numbers, explicit +/− markers, colored additions/deletions and keyboard-operable jump buttons; deletion jumps to its surviving new-source boundary (clamped at EOF). Prefer the first changed nonblank line over an inserted blank separator. Jump selects that line in the actual textarea DOM value and synchronizes gutter scroll. If the editor no longer matches the result or the edit was undone, the old diff remains visible but jump is disabled rather than navigating stale coordinates.

## Direct PDF conversion

- `POST /api/robin/resume/import` is a same-origin, bounded multipart endpoint. Exactly one PDF, nonempty and ≤5 MiB; request bound adds 64 KiB for multipart overhead. Validate the PDF signature, then check the full page count (≤5) before extraction. No first-N-pages conversion or silent truncation.
- `lib/resume-pdf.ts` reuses `lib/pdf-render.ts`'s Poppler `pdfinfo` / `pdftotext -layout` helpers: fixed filenames in temporary directories, no shell, bounded subprocess timeout, cleanup in `finally`. Check cancellation between steps; an already-running parser finishes/timeout-cleans locally, but does not subsequently start generation. Missing Poppler, encrypted/damaged files, truncated text (60,000 characters) or a page with fewer than 40 non-whitespace characters produce explicit failures. The heuristic is a scan/blank-page guard, not proof that every visible glyph was extracted.
- Selecting a PDF starts conversion with the configured default model. Only extracted text is sent to the model, not PDF bytes. A conversion request does **not** mix in the old scoring CV, current editor source or JD. It asks for faithful transcription/formatting, not rewriting or invented qualifications. A valid complete result directly updates the matching editor draft, shows its diff and offers Undo; it still requires Save. An in-flight user edit blocks replacement. Extracted text, original filename and page count appear with the proposal for review. Input/output remain in the normal Pi transcript; the original PDF is not retained by the workspace.
- This is reconstruction, not recovery of the original `.tex`: fonts, columns, embedded graphics and hidden hyperlink targets can be lost. Scans/mixed unreadable pages require OCR before uploading; there is no OCR or image-model fallback. Conversion itself does not execute LaTeX. Once applied, the editor's separate preview service compiles the resulting draft as described below. Compare it against the original PDF; a successful compilation does not validate candidate facts.

## Live PDF preview

- `components/robin/ResumePreview.tsx` previews the **current unsaved source**, including manual edits, PDF conversion, agent edits and Undo. A 900 ms debounce avoids a compile per keystroke; rendering still takes additional time. Editing, pausing or unmounting cancels the pending timer/request. Late responses cannot replace newer pixels. Auto preview can be paused; Recompile while paused is one-shot, not an implicit re-enable. No compilation shifts focus or writes `resume.json`/the scoring CV/application PDF.
- Desktop puts the numbered editor beside PDF preview, with agent/diff below the preview; the editor remains sticky. The header's PDF preview button explicitly focuses/scrolls to it, especially on phones. Poppler JPEG pages work on iOS without an embedded PDF viewer and cannot execute PDF scripts. Page/zoom controls scroll within the preview. The current PDF is a tab-local Blob URL, revoked on replacement/unmount; explicit Download PDF does not update the application's stored PDF.
- While source differs from the last successful snapshot, retain that image, visibly label it **previous preview**, and disable PDF download. This also applies to blank/oversized source, errors, paused preview and in-flight requests. Never label old pixels current in the render before an effect runs. Compiler failures keep both draft and last good render; diagnostics are bounded, missing-glyph/layout warnings get a visible warning even if compilation succeeds. Last successful diagnostics are labeled old when their source is no longer current.
- `POST /api/robin/resume/preview` is same-origin/JSON-guarded, bounded at 1.25 MB wire / 200 KB source, `no-store`, Node runtime. `lib/resume-preview.ts` does not use an agent or touch domain storage. It returns at most 5 complete pages (JPEGs), the compiled PDF and bounded compiler messages; never partial first-N-page success. Missing tools/packages/isolation produce errors, not an unsafe fallback or network download.
- **Security boundary:** currently macOS Seatbelt (`/usr/bin/sandbox-exec`) only. `--untrusted` alone is not sufficient: Tectonic's filesystem provider explicitly does not contain relative paths. All three programs (Tectonic, `pdfinfo`, `pdftoppm`) run under deny-by-default profiles. Only the per-request canonical temporary directory is writable; TeX cache is read-only. Reads are restricted to the working directory, prepared cache, system libraries/fonts and Homebrew installations; personal files, project files, other temporary directories, network and other executable paths are inaccessible. File metadata/root-directory listing are allowed for loader operation, not arbitrary file contents. The fixed noninteractive Bash launcher sets CPU/file/descriptor limits and execs fixed argument arrays, never source text. No inherited credentials/environment, shell escape or arbitrary shell commands. Poppler also stays inside isolation; PDFs are never processed by the ordinary unsandboxed helpers.
- One compiler pipeline per server process, no queue (busy callers get 429). Each subprocess has a 20 s wall limit, 15 s CPU limit, file/descriptor limits and 128 KiB captured-output cap. PDF ≤8 MiB, JPEGs ≤10 MiB total, at most 5 pages. No hard address-space/RSS guarantee is claimed. Abort/overflow kills the child and waits for `close` before cleanup/releasing the slot. Files are removed in `finally`; no persistent source/PDF cache or transcript is created. Cache readiness checks never silently enable downloads.

### Local setup (macOS)

```sh
brew install tectonic poppler
node --experimental-strip-types scripts/prepare-resume-preview.mjs
```

The operator-run preparation script compiles only fixed public Latin/CJK templates, never a supplied document or API input. It may download Tectonic's standard bundle resources into `~/Library/Caches/pi-web-resume/tectonic`; it uses a disposable HOME and does not read the operator's Tectonic config. Runtime requests always use `--only-cached` **and** OS-denied networking, with read-only shared resources. Re-run preparation after a compiler update. Additional/custom classes, system fonts and packages not warmed by the script may fail; do not loosen isolation to make an arbitrary uploaded document work. Non-macOS deployments need an independently isolated implementation before enabling preview.

Prepared packages include geometry, enumitem, hyperref, fontspec, fontenc, inputenc, lmodern, xcolor, tabularx, titlesec, fancyhdr, multicol, ragged2e, changepage and fontawesome5. The fixed `extension/robin/fixtures/resume-legacy.tex` additionally warms **T1/Latin Modern and explicit Computer Modern/EC** at 10/11/12pt class sizes with 9pt compact body, bold/italic/small-caps/sans/mono text, tables, headings and bullets. Merely loading fontspec/TU does not warm these resources: the original setup missed `t1lmr.fd`, TFM and Type 1 font files, causing valid `fontenc → inputenc → lmodern` resumes to fail at `fontenc.sty:112` (`ecrm1000 not loadable`). The same fixture must render offline under isolation in regression tests; never fix this by stripping fontenc, rewriting the user's source or enabling runtime network access. Existing installations should rerun the setup script to receive this coverage. Chinese uses `\documentclass[fontset=fandol]{ctexart}` (bundled fonts, not machine-specific names); the agent is told this, but still cannot see/claim compilation results. The default template's bracket placeholders are braced after `\item` so TeX does not interpret the entire sentence as a bullet label and place it outside the page.

### Font coverage regression: fractional sizes

Warming a 9pt body plus 10/11/12pt document classes was still incomplete: `\fontsize{8.4}{10}` selects the separately cached `ec-lmr8.tfm`, so a valid contact line failed again. `resume-font-sizes.tex` now ships actual PDF glyphs across 18 size samples (5–51.59pt, including 8.4 and 21), roman/sans/mono families, medium/bold weights and upright/italic/slanted/small-caps shapes, for both Latin Modern and Computer Modern/EC. The matrix also renders URLs and inline math at every size: `url` may initialize OT1 math fonts even in T1 text, and warming only text still leaves `cmr8` (or LM math metrics) missing. Actual output is essential: selecting a font or creating an unused box may warm metrics but not its outline files. This is standard-font coverage, not a claim that every custom font/package exists. Native offline tests compile both matrices plus a separate screenshot-shaped 8.4pt-contact/21pt-heading document; browser tests exercise that configuration through the real HTTP compiler without rewriting or saving source. Rerun preparation for existing installations; runtime isolation/network policy remains unchanged.

## Checks

```sh
node_modules/.bin/tsc --noEmit
node --experimental-strip-types --test lib/resume-preview.test.mjs app/api/robin/resume/preview/route.test.mjs components/robin/resume-changes.test.mjs extension/robin/resume-domain.test.mjs lib/resume-agent.test.mjs lib/resume-pdf.test.mjs app/api/robin/resume/route.test.mjs app/api/robin/resume/import/route.test.mjs lib/text-recovery.test.mjs lib/i18n/registry.test.mjs
node --env-file-if-exists=.env.local --experimental-strip-types e2e/resume-workspace.mjs
node --env-file-if-exists=.env.local --experimental-strip-types e2e/resume-preview.mjs
node --env-file-if-exists=.env.local --experimental-strip-types e2e/board-navigation.mjs
```

Browser tests mock all business/AI calls (no real CV changes or paid inference), cover desktop/phone/short landscape, PDF upload→direct editor update→diff without autosave, empty workspace conversion, conversion refusal, numbered replacement/addition diffs, keyboard line jumps and gutter synchronization, undo and subsequent manual edits, source recovery, slow writes, stale results, malformed output, conflicts, cancellation and UTF-8 `.tex` import/download. PDF tests use real Poppler with synthetic PDFs. Model orchestration is tested with a stub runner; this does not certify a particular model's conversion quality. Preview integration tests use real offline Tectonic/Poppler for synthetic Latin/CJK/multipage source, syntax/missing-package/page-limit failures, missing-glyph warnings, cancellation and sandbox attacks (absolute/relative/symlink reads, outside/cache writes, other executables and local network). They skip compiler-dependent cases when preparation is unavailable. `e2e/resume-preview.mjs` requires preparation: it verifies real HTTP compilation/cancellation, then controls response races with synthetic renders; covers debounce, stale/error preservation, focus, pause/manual retry, agent edit/undo, download, paging/zoom and responsive layouts. No personal resume writes or paid model calls.
