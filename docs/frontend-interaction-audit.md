# Frontend interactions and Incoming backend audit

## Scope and evidence

This is a first-pass audit, not a claim that every state of every page is certified.
All 36 current `app/**/page.tsx` routes were inventoried. Browser coverage focuses on
Incoming (mail / AI weekly / podcasts), Events, Notes, Product, Obsidian, Research,
and navigation across Dashboard / Jobs / Learning. Detail pages, all learning
courses, CRM/outreach, recordings, tools, settings and chat are **not** exhaustively
interaction-tested in this pass. Existing unrelated working-tree changes remain intact.

Browser mutation tests use fixtures; no personal drafts, ideas, calendar entries,
weekly editions or summaries are written. No live paid research, YouTube scan or
Telegram delivery was initiated. Browser video thumbnails can still load from YouTube.
Desktop viewport tests are not real iPhone/Safari or low-end-GPU performance tests.

## Implemented and checked

| Before | After | Why |
| --- | --- | --- |
| Podcasts occupied a separate global navigation entry | Email / AI weekly / Podcasts selectors inside Incoming; `/podcasts` redirects with query context | Reduce top-level navigation without breaking bookmarks; this is the existing **podcast** feature, not a newly built blog reader |
| Hidden weekly view polled every 10 seconds | Source mounts on first visit, retains drafts afterward, pauses automatic reads while inactive, refreshes on return | Avoid hidden work without discarding reading/filter/preference state; global badge reads remain intentional |
| Cancelling a poll relied partly on transport abort | Effect cleanup also advances the response sequence | Late transports that ignore abort cannot change retained panel data |
| Podcast refresh failures disappeared once any old data existed | Keep the shelf and surface refresh errors; empty category has a clear message | Old data should not masquerade as a successful refresh |
| Podcast/event handlers relied on a later disabled render | Synchronous ref guards reject repeated activation before React commits | Prevent duplicate scans, saves and summary submissions |
| Event date navigation always smooth-scrolled; image hover applied on touch | Move focus to the results heading; keyboard/reduced-motion scroll instantly; image zoom is pointer-hover-only | Respect keyboard and motion preferences without new animation dependencies |
| A failed old note save could be requeued after a newer save had entered the queue | Requeue only the still-current draft | Reproduced in Chromium: an extra PATCH restored old text on pagehide; the regression now passes, and the latest failure still retries |
| Completed podcast summaries could be regenerated by a repeated POST | Reuse the stored per-video summary under the run lease | The existing concurrent-run guard did not prevent sequential duplicate model cost |
| YouTube response bodies were read in full; caption fetches could follow redirects | 8 MiB decoded-body ceiling before parsing, streaming cancellation, redirects refused | A model prompt character limit is not a network memory bound |

| **P2 — Jobs idle requests** stayed at 4–5 seconds | Sweep/scoring: 4 seconds running; applications: 5 seconds running; all three: 60 seconds idle | Preserve progress feedback without idle high-frequency reads; visibility/manual refresh remain immediate |

## Follow-up: learning progress retry semantics

`LearningPanel.tsx` (shared by Dashboard and Learning Hub) separates failed reads from unconfirmed writes. Reload progress only performs GET; Retry save retains the original `{ step, completed }`, including completion undo and course-map checkboxes, even if a poll changes `next` or `lastCompleted`. The existing domain operation sets an idempotent desired state, not a toggle. A synchronous guard prevents same-frame duplicate saves/retries and overlapping manual reloads. A new explicit progress change supersedes the previous failed operation; background reads alone do not hide it.

An acknowledged PATCH has its own saved notice. A subsequent failed refresh is a read failure, never a reason to repeat that PATCH. Network write failures are labelled “Save not confirmed”, since loss of a response cannot prove the server did not commit. Retry state is local to the mounted panel; no offline queue, automatic retry, cross-tab conflict protocol or storage change is introduced. English, Simplified and Traditional Chinese recovery messages identify the step and desired state.

Checks: `LearningPanel.retry.test.mjs` reproduces the prior missing write retry and covers exact targets, polling drift, read/write separation, acknowledgement and single-flight guards. `e2e/learning-retry.mjs` runs against fixture-only APIs on Learning Hub (English desktop / Chinese 390px) and Dashboard, including slow/failed requests, completion undo and course-map checks. No real learning progress is written.

## Follow-up: cross-workspace interaction and material hierarchy

Design recommendation: unify **navigation, reading and assistant roles**, not every page's layout. Glass is a navigation material, not a reason to blur documents or merge workflows.

| Workspace | Interaction direction | Material boundary |
| --- | --- | --- |
| Daily / calendar | Date and actual tasks first; secondary tools disclosed | Glass chrome; precise event/time geometry |
| Incoming / jobs | Keep source/filter context and a predictable return | Compact source navigation; readable lists and receipts |
| Learning | Current course/problem and progress first | Shared frosted resource rail; opaque exercises |
| Notes / Obsidian | Editing, reading and canvas remain distinct | Shared ground/chrome; solid text and drawing surfaces |
| Research | Project → goal/notebook, papers, discussion | Frosted filing/resources; clear view selector; opaque notebook/PDF |
| Product | Idea → experiment/evidence; partner optional | Frosted directory; clear view selector; separate opaque document |
| Tools / settings | Input → explicit action → result; destructive actions reviewed | Grouped controls; stable, readable results and confirmation |

This is a hierarchy recommendation based on the current code/documentation, not a new usability study or an assertion that all pages were redesigned. This pass implements Product/Research material gaps and the shared resource rail used by Learning. It does not modify the other rows' workflows.

Previously Product/Research only opted structural ground into Glass: Research kept an opaque square filing sidebar and full-width underlined views; Product's document met the workspace edges. The new surfaces reuse existing material tokens and preference fallbacks. No new dependency, background animation, business API or per-card filter is introduced. Large directories/resources use CSS frost only; only the small view selector joins existing refraction. Product's narrow directory additionally supports Escape/focus return and moves focus into the selected reference view. Its mobile partner label is shortened to avoid squeezing the page title.

Checks: 26 focused component checks; expanded fixture-only `e2e/workspace-ground.mjs` (both Glass palettes, research home/project, 320/375/812-landscape/1440px, unfiltered documents, high contrast/reduced transparency, ordinary-palette isolation, directory keyboard focus, history and discussion draft retention); existing `research-visual.mjs`, `product-autosave.mjs`, `product-lab.mjs`; TypeScript and changed-component ESLint. Screenshots: `/tmp/workspace-ground`. No personal records or model calls. Browser emulation does not certify real iPhone/Safari performance or keyboard behavior.
