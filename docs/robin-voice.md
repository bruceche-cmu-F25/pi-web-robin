# Robin voice — companion and local dictation

## Robin task interaction (default voice mode)

The global button defaults to **Robin · task actions / Boson speech**: local Whisper → the existing Robin Act conversation → real task-domain receipt → Higgs TTS 3. Boson does not interpret instructions or choose tools on this path. This restores the serial ASR/Agent/TTS latency; it is not the sub-second Realtime trial. Old `robin:voice:engine` preferences do not silently select that trial; deliberate choices now use tab-local `robin:voice:engine-v2`.

- Entering Robin voice enables direct, explicit task instructions, with a visible disclosure and Undo; there is no extra permission checkbox. Discussion and ambiguous references still require clarification. This is not an authorization for arbitrary tools. The API retains `allowTasks: false` for explicitly read-only callers; the browser's Robin mode sends true. Date-only tasks do not create timed notifications. No permanent delete, email, calendar write or payment is available.
- `/api/robin/voice/interaction` is authenticated and origin/JSON guarded. POST accepts a bounded utterance and stable timestamped request id, not tool names, snapshots or invented history. `runRobinVoiceTurn` shares the default Robin session id, local-clock context and cross-process turn lock. Because SDK registration allow-lists are fixed at runtime creation, it rebuilds only the idle wrapper against the same transcript with `todo_list` and (when enabled) `voice_task`; it disposes that narrow wrapper afterward. The next typed turn resumes the same file with its normal scope. This is not the arbitrary coding Chat's agent/context.
- `voice_task` is model-only and inactive by default. Its server-owned, session-bound, expiring grant exists only during this turn. It allows one mutation: add, edit title/date/range/link, complete, reversible abandonment, or undo. The prompt treats discussion/tentative plans/quotes as data, asks for ambiguity, and prefers the corrected date in an utterance. Intent recognition is still model inference, not a guarantee of zero mistakes.
- Task ids and revisions come from real domain records. Edits/undo refuse intervening changes. Undo-add abandons rather than permanently deletes. Other undo restores the server snapshot, refusing to displace a newly chosen next task. A saved operation is shown as a receipt and spoken using server-generated text, not the model's success claim. Model-only chat remains separate from execution proof.
- The bounded assistant journal lives alongside its session pointers in **unmigrated `assistant.json`** (512 entries, 24-hour retention); it is not a new task collection or an unversioned SQLite runtime-state filename. Pointer resets preserve the journal and all updates share its lock. A fence is saved before touching task storage; duplicate POST/tool attempts cannot repeat that request. New ids older than ten minutes are refused, including after old entries are pruned. This is **not an atomic transaction across the journal and tasks**, nor an exactly-once/power-loss guarantee: a crash/storage error between the write and its receipt remains uncertain and must be checked, not replayed.
- End/interruption cancels capture/playback, not submitted writes. A late task receipt is retained without late speech. ASR can transcribe the next correction while a write is pending; dispatch waits for its real receipt. Unknown outcomes block automatic follow-ups. Reload restores the pending id and only GETs its outcome; no microphone, authority, action POST or TTS is restored. Clear requires explicit acknowledgment for an unresolved request and never deletes task/server history.
- Typed/edited submissions during an active Robin voice call also request speech. A sound onset while a task turn is pending does not permanently cancel that reply: hold its speech until ASR resolves; an empty segment resumes the held reply without another Agent/tool request. Real recognized follow-ups supersede it. Actual playback still stops immediately on speech onset. End, explicit Stop reply, hidden pages and late generations never auto-resume. Robin decodes the TTS WAV and starts an AudioBufferSource on the **same AudioContext resumed by the opening click**, rather than calling an HTML media element's `play()` after network waits. No new output context or per-reply click is needed. Sources are stopped/disconnected on interruption and End; late decodes are fenced. Speaking means a source started on the running context, not proof of physical speaker output. Normal replies show no playback button. Only an actual audio error offers `Retry speech`; it never repeats an Agent/tool request and reuses a decoded buffer when available (otherwise explicit synthesis is billed). No promise of acoustic noise/speaker identification.
- Main Chat launches retain the existing launch-time text sink, saving utterances and confirmed reply text without prompting that coding session. The actual tools/conversation belong to Robin Act. Sink failure does not undo a task or reconnect audio. The primary trace link points to Robin's real session. Other launches keep panel text and the Robin transcript; neither audio nor provider keys are journaled.
- UI uses the existing dialog, touch targets and foreground microphone owner. A pending request shows ordinary Waiting for reply, not an uncertainty card or Check result button. Only a genuinely unconfirmed outcome/recovery shows that card; a successful task mutation shows its receipt. Audio goes to local Whisper; recognized text goes to Robin's configured model; reply text goes to Boson TTS (legacy TTS selection rules below still apply). No automatic provider fallback. Long-term keys stay server-side. Actual Boson spend remains unavailable; no monetary estimate is presented as a bill.

Checks: `voice-action-domain.test.mjs` on SQLite and JSON; interaction route tests; Robin session lifecycle tests; `e2e/voice-interaction.mjs` with mocked Robin/ASR/TTS and real browser worklet/media, including checkbox-free entry, typed-input speech, empty-ASR noise during a pending turn, automatic output even with media-element `play()` forced to reject, use of the already-running microphone context, audio-error-only retry, same-task follow-up, late receipt after End, undo, GET-only recovery and 320/390/1440px layouts. These do not verify real model intent decisions, physical phones, noise, echo, latency or billing.

## Boson Realtime trial (explicit retained mode)

Transcript → Voice mode can explicitly select **Boson Realtime · chat trial** or the original read-only Agent below; neither is the default or an automatic fallback. Switching stops the old microphone/socket before starting the selected mode. All paths use the existing compact dialog and capture owner.

- `GET /api/robin/voice/realtime` checks Boson key presence only. An explicit start acquires the microphone/AudioContext in the click, then `POST {}` to that authenticated, origin-guarded route mints a **60-second ephemeral credential** from the fixed Boson HTTPS endpoint. The server-only API key never leaves the server. Responses are bounded, no-store, masked on failure, and minting is limited to 10 attempts/minute per process. There is no background mint, retry, provider fallback or key storage in the browser. The ephemeral credential is intentionally given to the authenticated browser in memory; it is a provider credential, not a Robin tool authorization or a server-enforced spend cap.
- The browser connects directly to `wss://api.boson.ai/v1/realtime?model=higgs-realtime`. Unlike the original mode, **microphone audio goes to Boson**, not local Whisper. `higgs-realtime` handles speech-to-speech, semantic turn detection and interruptions; optional `higgs-stt-3.1` provides user captions. `default` voice, PCM16 mono 24 kHz in/out, 256 output-token limit, `tools: []`, `tool_choice: none`. No page content, quotes, existing transcript, email, task or calendar data is sent. The trial cannot query or modify Robin records. Streamed model speech is not fact-checked and cannot serve as an execution receipt.
- `useCompanionMicrophone` exposes an optional raw PCM callback and the gesture-unlocked AudioContext; realtime bypasses its local utterance gate entirely. A continuous, fractional-phase area-averaged resampler handles 16/24/44.1/48/96 kHz input. The bounded PCM player schedules chunks immediately on that same context; it never waits for a complete WAV. Speaking is tied to the running playback clock, not a received network chunk. Transcript reports **server-detected turn end → playback**, which excludes the provider's endpoint-detection wait and physical output latency; it is not a mouth-to-ear benchmark.
- Server speech-start clears queued playback and fences late chunks for the interrupted response. Cancellation/truncation reports the locally played position, including interruption after generation completed but playback had not. Mute disables real tracks and clears pending input without cutting off output. End/Escape, hidden/offline/pagehide, device loss, suspended audio, 120 seconds idle, or the **10-minute client trial cap** release capture/playback and close the socket. No automatic reconnect; a restart is a fresh conversation. A 25-second connection deadline and 30-second first-playback deadline stop stalled sessions. Network backpressure and output queue limits fail closed rather than accumulating delayed audio. Server usage is currently null, so the UI does not invent a dollar counter or billing guarantee.
- The panel shows the latest 12 messages in page memory. **Starting from the main Chat composer also appends received captions to that Chat session**, including a fresh composer (one `ensure_session`, no prompt). The launch captures the destination; later navigation cannot retarget pending saves. User transcription completions and finished/locally interrupted assistant captions are saved in order of receipt through the owning RPC manager's `append_voice_transcript`, with bounded text, per-message idempotency and an expected-leaf check. Busy or changed branches refuse rather than inserting into a tool exchange or another branch. The existing storage-failure guard still owns persistence. A failed/uncertain save retains its exact request in memory with an explicit Retry; reload before retry can lose unsaved text. End flushes received partial assistant text, not audio or captions that never arrived. Clear only clears the panel, never saved session messages.
- Saved messages keep user/assistant roles and explicit voice provenance. Assistant text is generated speech, not proof every word played or that a tool executed. Boson reports no usage; Pi's required usage fields are zero placeholders, **not a claim of free usage**. Persistence starts no model turn, tools, auto-name or completion notification. The next normal Pi prompt reads these messages from its authoritative session manager. No old chat history is uploaded to Boson. Launching elsewhere remains panel-only, disclosed in the dialog; there is no inferred hidden target session. Audio and credentials are never persisted. Existing same-page claims and same-origin companion BroadcastChannel ownership remain; no lock-screen, background or cross-device promises.
- Empty `response.output_audio.delta` chunks are valid no-audio boundaries observed during live interruption. The player ignores them without allocating/stopping nodes; malformed nonempty PCM remains an error. Audio exceptions are reported as audio failures, not generic provider failures; response completion clears the no-audio watchdog too.

## Original companion: foreground, read-only (explicit fallback)

The root layout mounts `GlobalCompanion` on every application page except Login, with **no floating Robin launcher**. `CompanionLauncher` lives in the empty main Chat composer's primary-action slot (typing/attachments restore Send), the phone Home header, and other workspaces' navigation. The waveform icon is distinct from the existing dictation microphone. One click directly requests continuous capture in the user gesture; the small native voice dialog opens with only status, Mute and End, plus a Transcript disclosure. No second Start screen, automatic keyboard, permanent transcript/form or configuration wall. The short footer states automatic sending after pauses and billed speech; Read-only stays visible. Readiness failure stops capture and offers Settings, not a pretend connection.

Mute disables audio tracks, resets the current segment and prevents automatic submission while muted, but lets Robin finish speaking; End/Escape releases capture and pending reply/audio and closes the dialog. Closing never leaves a hidden live microphone. Native modality supplies focus containment; a navigation launcher closes the phone drawer first, and End returns focus to the opener or visible menu trigger. Text, deliberate quotes, manual Finish, corrections, trace and privacy/settings live under Transcript; incomplete drafts reveal it automatically. Client-side navigation retains the owner. Full document navigation restores only the latest 12 text messages and last reply record from tab-scoped `sessionStorage`; it never restores voice consent. Clear removes that local transcript, not server records.

This is a new read-only interface over the **existing** `runAssistantTurn("readOnly", …)`, not another Agent implementation or realtime voice provider. Its available reads are todos, calendar, jobs, interview rounds and Gmail. It cannot create tasks/reminders, change records, browse arbitrary pages, read all workspace contents or claim an action was performed. Explicit changes still use the original page controls/Act channel. Automatic ASR is not authorization to write; the server ignores client mode/tool flags. The existing stateless read-only mode creates a trace per turn; bounded recent messages provide conversation context, not a new durable memory store.

- Context is an allow-listed path/query reference plus text the user explicitly quotes (up to 2,000 characters), not DOM scraping or cross-origin frame access. References/history/quotes are untrusted data. Arbitrary URL queries, OAuth parameters, passwords and direct editable-field selections are excluded.
- `companion-audio.ts` uses local RMS segmentation, approximately 180 ms onset, 1,500 ms silence, 400 ms pre-roll and a 45-second cutoff. This is **not** semantic turn detection, diarization, wake-word detection or production noise robustness. Duration cutoffs and obvious unfinished connectives retain a reviewable draft; corrections require explicit Send. ASR segments are serialized with a bounded backlog. **Done speaking** is the manual alternative.
- `companion-capture.js` sends mono PCM through an AudioWorklet and outputs silence. Browser resampling produces the existing canonical 16 kHz WAV; local Whisper remains ASR, Boson/legacy TTS remains speech output. No new dependency or cloud speech-input provider.
- Starting to speak interrupts pending read-only replies/audio; generation guards discard late results. The interface says Speaking only after the actual media `playing` event, Reply received only after a validated response, and Reply not confirmed on failures. No automatic retry. Text survives TTS failures; blocked autoplay exposes a native player. These are transport/playback states, **not factual verification or execution receipts**. Model answers and ASR can still be wrong.
- The Agent returns separate screen and short spoken fields, normally one useful sentence, without pleasantries/repetition/automatic follow-up questions. Negations, dates, amounts, risk and uncertainty must survive in both. Speech over 240 characters or unsuitable for speech is withheld, never mechanically truncated. Malformed structured output is unconfirmed. A conservative execution-claim guard refuses common false completion wording; it is not a guarantee against all hallucinations.
- Hidden pages, offline, pagehide, lost device, suspended audio context, 120 seconds without captured speech, explicit End and another voice control claiming the mic all stop capture. Same-origin companion tabs announce ownership through BroadcastChannel when available; this is **not** a cross-device lock or a guarantee covering legacy controls in other tabs. No lock-screen/background listening, unsolicited spoken reminders or device handoff is implemented.
- The panel follows the visual viewport, has 44px touch targets/16px input, and adopts the app's document language. English and Chinese copy are standalone because the root owner sits outside the page-scoped i18n providers. No animation or new theme runtime.

Code: `extension/robin/companion.ts`, `app/api/robin/companion/route.ts`, `GlobalCompanion.tsx`, `useCompanionConversation.ts`, `useCompanionMicrophone.ts`, `companion-audio.ts`, `public/robin/companion-capture.js`.

Checks: `node --test extension/robin/companion.test.mjs components/robin/companion-audio.test.mjs app/api/robin/companion/route.test.mjs` and `PLAYWRIGHT_CHANNEL=chrome node --env-file-if-exists=.env.local e2e/companion-voice.mjs`. Browser tests exercise real WebAudio/worklet/native playback with a generated microphone stream and mocked Agent/ASR/TTS: one-click entry, three-control default, actual track muting without interrupting playback, short pauses, repeated turns, barge-in, late audio/permission, uncertain replies, incomplete drafts, background stop, text-only navigation recovery, context filtering and 320/390/1440px layouts. `e2e/chat-voice.mjs` also checks the inline primary-action slot, draft/attachment-to-Send switching and absence of a floating launcher. ## Existing dictation and explicit action voice

**Speech input runs on the Robin host with whisper.cpp. No cloud speech key is needed.** Phones and other computers record in their browser and upload to the existing authenticated Robin HTTPS endpoint. Two explicit destinations share one capture UI:

- **Legacy `RobinVoice` component** (no longer the phone Home entry; replaced by the global companion above): Desktop keeps only the Search/Act input's dictation microphone, not a second standalone launcher. Tap starts recording immediately; **Done speaking**, a hold/release, or the time limit only transcribes into a visible editable draft. The user must click **Confirm and send** to send the edited text to the **existing default Robin conversation** (`POST /api/robin/assistant`). Closing/reopening retains that in-memory draft without opening the microphone again; explicitly recording more appends rather than replacing corrections. Clearing all text leaves the field editable and Send disabled. This is page-lifetime state, not crash/navigation recovery. No second agent, new mode, tool expansion or separate memory. The working/result state and actual execution-record link remain visible. Closing this UI never cancels/undoes or automatically retries a dispatched turn; failed/uncertain responses direct the user to the execution record.
- **Dictation**: microphones in Dashboard Search/Act, Cmd/Ctrl+K, shared `AgentPanel` and main `ChatInput` use the same tap/hold capture but only insert text into their existing draft. Search never executes. Chat preserves current selection, attachments, undo and draft persistence; sending, commands, IME, session/cwd changes and unmount invalidate pending recognition. The owning panel's original endpoint/model/tool scope stays unchanged.
- Main Chat's dictation uses a **compact inline capsule beside the existing composer**, not the floating voice dialog: cancel, actual left-moving volume history and stop-to-transcribe. It does not blur a focused textarea, replace its DOM or move the original held trigger. Success inserts through the existing selection/undo/attachment-safe path, releases the voice layer and removes the bar; a live-region receipt says text was inserted, never a lingering “microphone off” success panel. Errors remain inline with retry and a settings link. The original Send button remains the explicit submission step; no arrow that silently sends unreviewed recognition. Dashboard's standalone entry now also requires separate text review and Send; other dictation destinations keep their original draft/endpoint.
- Custom panels, the research thread and compact quote-question composer remain **not integrated**.
- **Gesture rules**: short tap latches recording; another tap finishes. A ≥300 ms hold with known permission finishes on release. Moving up ≥64 px changes the visible instruction to **Release to cancel**. A visible Cancel button and Escape are non-gesture alternatives. First/unknown permission, or release before permission resolves, always stays in tap mode; no permission-dialog release can authorize submission. Pointer cancellation/lost capture cancels, never sends. Repeated keyboard events and trailing native clicks do not duplicate dispatch.
- A nonmodal manual popover keeps the held trigger interactive. Phones get a bottom panel, desktop a compact floating panel; older Safari gets a fixed fallback inside the owning dialog/body. Opening does not focus a text field. **Listening** appears only after MediaRecorder starts; real Web Audio level bars and elapsed time distinguish capture from recognition/agent work. Float32 RMS from a 1024-sample window maps -60 to -20 dBFS onto a visible envelope, with 120 ms attack / 240 ms release. Nine small mirrored rounded bars in the floating panel show the recent level spreading from the centre (a stylized level indicator, not a spectrum). Only transforms/opacity change outside React; silence settles to dots, reduced motion keeps dots stationary and changes opacity. No decorative looping waveform. Another panel claiming the microphone dismisses the old voice panel.
- **Visuals**: the floating panel is a compact capture row (cancel, central listening/status + real level indicator, 44px stop), not a large titled sheet with a second full-width record action. Recognition has three small opacity-only progress dots, stationary under reduced motion; these indicate processing, never microphone level. Review shows an unboxed 16px textarea and explicit Send; long results scroll within a bounded area. Voice options contains privacy, settings and optional TTS controls, absent during capture. The panel reuses Glass / Dark glass's overlay tint, CSS frost, directional thin rim and shadow tokens; foreground text stays unfiltered. There is no nested blur or fake looping audio waveform. Ordinary themes remain opaque; reduced transparency, high contrast and forced colors restore solid surfaces and defined borders. This is the shared web material, not a claim of native Apple refraction.
- Up to 60 seconds. The time limit is **not** consent to send: it produces a reviewable draft, with explicit Confirm and send for the global entry. Near-digital-silence audio is rejected before ASR (not a general VAD/speech detector). No auto-stop on pauses, live partial recognition, wake word or full duplex.
- Optional Boson TTS (configured in Settings) or legacy Beijing DashScope TTS remains explicit and hidden when unconfigured. A separate checkbox opts into spoken excerpts when Send is clicked; saving a key never synthesizes speech. Settings has an explicit billed Boson preview. These existing controls do not use the companion's separate short spoken field; a durable device-wide speech preference remains unimplemented.

## Install once on the host

The development Mac has **whisper.cpp 1.9.5** and the verified multilingual **Small Q5_1** model installed. Nothing needs installing on client devices apart from access to the private network when using Tailscale.

For another Mac:

```bash
brew install whisper.cpp
mkdir -p "$HOME/.pi/robin/models"
cd "$HOME/.pi/robin/models"
curl --fail --location --output ggml-small-q5_1.bin.part \
  https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-small-q5_1.bin
printf '%s  %s\n' \
  ae85e4a935d7a567bd102fe55afc16bb595bdb618e11b2fc7591bc08120411bb \
  ggml-small-q5_1.bin.part | shasum -a 256 -c - && \
  mv ggml-small-q5_1.bin.part ggml-small-q5_1.bin
```

The model is 190,085,487 bytes; Homebrew runtime/dependencies are additional. Do not use an English-only `.en` model or a Python `.pt` checkpoint. There are no model downloads at request time.

Defaults: find `whisper-cli` on PATH, then `/opt/homebrew/bin/whisper-cli` or `/usr/local/bin/whisper-cli`; load `~/.pi/robin/models/ggml-small-q5_1.bin` (`ROBIN_DATA_DIR` relocates the data directory). Optional server-only overrides:

```dotenv
ROBIN_VOICE_WHISPER_BIN=/absolute/path/to/whisper-cli
ROBIN_VOICE_WHISPER_MODEL=/absolute/path/to/ggml-small-q5_1.bin
```

These are separate from the long-recordings/Telegram Python Whisper adapter's `ROBIN_WHISPER_BIN`; that adapter and its model remain unchanged. Environment changes require reloading the existing server; do not start a second dev instance. Installing the default binary/model needs no environment edit: **Check configuration** rechecks their presence.

`GET /api/robin/voice` returns `configured` (local microphone engine/model presence), `ttsConfigured` (optional cloud configuration presence), and public engine names. Presence is not an inference, permissions, model-integrity or balance test. No private paths/keys are returned.

## Phone / other computer

1. Keep the Mac awake, online and Robin running.
2. For the existing private Tailscale HTTPS Serve entry, connect the other device to the same authorized tailnet; access rules must permit this Mac. Open the **existing Robin HTTPS URL**, not `localhost`, a LAN HTTP address, or a Whisper port. This does not enable public access or change Tailscale configuration.
3. Sign in with the existing Pi Web password. Allow microphone access in Safari/Chrome and keep the page in the foreground.
4. Tap the **waveform voice button** for continuous read-only conversation; pauses submit automatically, Mute silences your microphone and End stops the call. A field's separate **Dictate** microphone still only fills its draft for explicit sending. No model or speech API key belongs on the phone.

Each capture obtains one stream; re-entrant starts during permission/recording/transcription are ignored. Finishing or cancelling still releases the microphone, never keeps it live just to suppress prompts. Safari's per-site Microphone → Allow can reduce repeated prompts; private browsing and Home Screen web apps may not retain/inherit that preference, and a website cannot grant itself persistent permission. See [WebKit capture controls](https://webkit.org/blog/7763/a-closer-look-into-webrtc/) and the [reported standalone persistence limitation](https://bugs.webkit.org/show_bug.cgi?id=280394). **Settings → Voice & microphone** (`/dashboard/settings#voice`) contains this guidance, browser permission status, HTTPS/support checks and separate recognition/TTS readiness. Chat General, the floating recording panel and inline capture errors link there in the same tab, like other site pages; the voice link first cancels capture, and browser Back restores the persisted chat draft. Opening settings never requests access. **Check microphone** explicitly requests one stream and immediately releases every track (even a late grant after leaving), without recording/uploading or sending a task. Unsupported permission queries are shown as unknown, not denied. The check does not grant permanent permission; site/browser/OS controls remain authoritative. Telegram's Voice notes configuration remains separate.

HTTPS, MediaRecorder, AudioContext and OfflineAudioContext are required. Safari's MP4 and Chromium's Opus recordings use the same browser decode/resample path to canonical mono 16 kHz PCM16 WAV. Unsupported browsers show an error rather than a cloud/browser-speech fallback. Backgrounding, locking or hiding the page ends/discards capture; continuous background recording is not supported.

## Processing and safety

- `POST /api/robin/voice?op=transcribe` retains web-password and Host/Origin guards, bounded upload size and strict canonical WAV validation. Browser capture stops at 59 seconds; overlong audio is rejected, not clipped.
- `local-voice.ts` launches the **local CLI**, not an HTTP Whisper server, with explicit model/input/output paths, automatic language detection, no translation and zero prior text context. No new port/service, Python/ML dependency or frontend model download.
- One inference at a time per Web process; another device receives a busy error, not an unbounded queue. The deadline is 60 seconds. Cancellation/deadline sends SIGKILL and waits for child close before releasing the slot or files. ASR itself performs no retry, cloud fallback or agent dispatch; only the standalone panel's explicit Send calls the existing assistant endpoint. `VoiceControls` has no automatic transcript-commit callback.
- Each request uses a fresh private temporary directory (0700), WAV file (0600) and bounded output. Files are deleted in `finally` on success, failure and normal cancellation. No audio/history is added to Robin's recordings store. **A host/server crash may leave private temp files in the OS temp directory**; this is not a no-disk or secure-erasure promise.
- Child stdout/stderr are discarded, and the environment is allow-listed; API keys/passwords are not passed. Responses expose safe error codes, not transcripts in error messages, command output, model paths or credentials. Successful transcript/readiness responses are `no-store` / `nosniff`.
- Silence, noise and brief/mixed-language speech can produce incorrect words or a different Chinese script. Always review dates, numbers and negations; local recognition is not proof the text is correct. Confirmed messages follow the existing chat/model privacy policy.
- Epoch guards discard late permission grants/results; closing, switching Search/Act, changing panels, unmounting, backgrounding, device loss, hidden controls and another panel claiming the microphone release resources. These legacy controls have no cross-browser-tab microphone lock (the companion's limited announcement is described above).
- Ending voice/playback does not cancel or undo a submitted assistant task.

## Optional TTS: Boson first, legacy Alibaba when absent

In **Settings → Voice & microphone** (`/dashboard/settings#voice`), paste a [Boson API key](https://www.boson.ai/workspace/api-key) and save. New accounts must [claim trial credit](https://docs.boson.ai/free-trial-credit) before calling the API. The saved key takes effect per request without a restart. `POST /api/robin/settings` with `section: "boson"` writes only `boson.apiKey` in the host's `secrets.json` through a locked atomic update (0600); reads return only presence/source, never the key or a tail. The key draft stays in Settings memory across category changes, is never placed in browser storage, and is retained after failure or a newer edit during a save. Navigation/reload warns on unsaved keys. Removal deletes only the saved Boson key; `BOSON_API_KEY` from the server environment becomes the fallback again.

Selection is saved Boson key → `BOSON_API_KEY` → legacy Alibaba configuration. Boson uses the fixed `https://api.boson.ai/v1/audio/speech` endpoint, Bearer authentication, `model: "higgs-tts-3"`, `voice: "oliver"`, `input`, `response_format: "wav"`, `stream: false`. This is text-to-speech only, not Higgs Realtime, an additional agent, voice cloning or a streamed PCM player. See [speech API](https://docs.boson.ai/api-reference/audio/create-a-speech) and [voices](https://docs.boson.ai/models/higgs-tts/voices). Language normalization is left on automatic detection for mixed text. No automatic retry or provider switch on failure.

**Preview Boson voice** sends only the visible, localized sample after an explicit click, consuming Boson paid/trial credit. It is disabled until Boson readiness is confirmed and key edits are saved. It reuses `useRobinVoice` for deadlines, playback, stop/unmount/hidden cancellation, object-URL cleanup and manual Play when autoplay is blocked; it never requests a microphone or an Agent turn. Saving/checking configuration never calls Boson. Presence is not a key/credit validity test. Main Chat remains dictation-only.

Without a Boson key, `ROBIN_VOICE_API_KEY` or `DASHSCOPE_API_KEY` enables `qwen3-tts-flash` / Cherry / Auto. `ROBIN_VOICE_ORIGIN` permits only the legacy Beijing DashScope origin or a Beijing workspace-specific origin. **These credentials affect TTS only, never recognition.** DeepInfra and a general provider selector are not implemented.

With TTS configured, the Voice replies checkbox opts into spoken reply excerpts. Sending is explicit (the standalone panel's Confirm and send, or the existing composer's Send). Reply consent is snapshotted from the current checkbox at dispatch, including changes made during transcript review, and is one-shot. These legacy replies remain **extractive** (up to three complete sentences / 600 characters); the global read-only companion instead requests a separate short spoken field. The full answer remains on screen. Without TTS configuration these controls are hidden and local dictation remains available.

TTS sends only excerpt text to the configured provider, Boson or Alibaba; no microphone audio goes there. Both paths use TLS, reject redirects, bound responses to 8 MiB/WAV, and share the two-operation ceiling and 60-second deadline. Alibaba downloads retain the fixed Beijing bucket allow-list and never carry API credentials. Browser autoplay may require manual Play. No claims of verified voice quality or paid provider access.
