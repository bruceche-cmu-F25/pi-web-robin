# Pi Web 的视觉语言（对齐 pi.dev）

Pi Web 是 pi coding agent 的浏览器界面，所以它的视觉语言直接取自 pi 官网
`https://pi.dev`：保留配色、排版分工与工程纸，**独立表面采用分层圆角**，不再照搬全局直角。
本文记录原始规则、当前 token 和可复用 class；原始官网规则不是当前形状的约束。

改样式前先读这一页；不要在组件里重新发明颜色或圆角。

---

## 1. 官网的五条规则

从 `https://pi.dev/style.css` 里读出来的、真正定义"pi 味道"的东西：

| 规则 | 官网做法 |
|---|---|
| **纸** | 页面底色是 canvas（暗色 `#161d27` / 亮色 moonstone `#ebe7e4`），上面铺 4px 细格 + 20px 粗格 + 粗格交点的十字刻度，像工程纸 |
| **面板** | 1px 细线（`--line`）、**直角**（`border-radius: 0`）、半透明面板色，让格子隐约透出来 |
| **排版分工** | 正文/标题是衬线（Plantin MT Pro，斜体作标题）；短、固定、低频的标牌和顶层操作用像素等宽大写；日期、状态和密集控件用常规等宽 |
| **强调色** | 只有一个冷蓝（暗色 `#6a9fcc` / 亮色 tidal blue `#335a8c`），所有 tint 都是这一个色相在固定 alpha 上叠出来的 |
| **按钮** | 默认是 `[ LABEL ]`，方括号用强调色；任务区可以显式使用一个实心 `.ui-action--primary`，以既有 accent/contrast 配对区分主次，不把所有操作都填色 |

另外两个小签名：选中项不铺灰色底，只保留左侧 3px accent 实色竖条，
以及方形、accent 染色的 6px 滚动条。

## 2. 字体

当前字号、行距、页头与控件的统一规则见 [排版规范](typography.md)：常规页头桌面 32px / 手机 24px，16px 字段下限不缩小标题输入框；正文行距保留阅读面与 `leading-*` 的明确设置。下文记录字体来源，不替代该规范。

官网用三个字体，两个能带、一个不能：

| 字体 | 官网用途 | 这里的处理 |
|---|---|---|
| **Departure Mono**（像素等宽） | 面板标牌、顶层导航、短主操作 | **已随包分发**，`public/fonts/DepartureMono-Regular.woff2`（22KB） |
| Commit Mono | 正文等宽 | 沿用项目原有的 Noto Sans Mono stack |
| Plantin MT Pro | 正文衬线 | Monotype 商业字体，**不能分发** —— 走官网自己的 fallback |

Departure Mono 是 Helena Zhang 的作品，SIL OFL 1.1，许可证按 OFL 要求放在字体旁边
（`public/fonts/DepartureMono-OFL.txt`）。它只有拉丁字形，所以 token 里跟了一条回退：

```
--font-pixel: 'Departure Mono', var(--font-mono);
--font-serif: Georgia, 'Times New Roman', 'Songti SC', STSong, 'Noto Serif CJK SC', serif;
```

中文标签会逐字回退到常规等宽，不会整行丢字。face 用 `font-display: block` 并在
`app/layout.tsx` 里 preload，避免首屏那些少量标牌在换字时抖一下。

像素字体是强调，不是默认 UI 字体：只给**短、固定、低频、全大写**的标牌或顶层操作。
日期、时间、代码、路径和对齐数值使用 `--font-mono`；设置控件、展开导航文字和保存反馈使用清晰的 `--font-ui`。长正文保留所在阅读面的字体，不将像素字铺进内容。设置的标签／正文基准为 13／14px，触控操作至少 44px；不以 10px 文案换取密度。

**要 100% 一致**只差衬线：把 Plantin 的 woff2 放进 `public/fonts/` 再加一条 `@font-face`
即可，但那份文件只能本地自用，不能随 npm 包发布。

## 3. Token 映射（`app/globals.css`）

`--pi-*` 是从官网抄下来的**原始色**，组件里永远不要直接用；语义 token 才是接口。

| 语义 token | 暗色（pi 深色主题） | 亮色（pi parchment 主题） |
|---|---|---|
| `--bg` | `#161d27` canvas | `#ebe7e4` moonstone |
| `--bg-deep` | `#0d1116` | `#dacbc2` parchment |
| `--bg-panel` | `#212730` | `#f4f2f0` |
| `--border` | slate 55% | warm-30 55% |
| `--text` / `--copy` | moonstone / 75% | evening blue / 86% |
| `--accent` | `#6a9fcc` 蓝 | `#8b513c` 赤陶（低饱和） |
| `--danger` / `--success` / `--warning` | terracotta / sage-green / sunkissed | `#9b3227` / 同色相的深色版 |

**两套主题的 accent 是反向的，这是故意的**：暗色留着 pi 自己的蓝；亮色走暖 —— 亮色是
parchment 纸，冷蓝放在暖纸上每一处都像外来件，而 pi.dev 自己的亮色 accent
（`--pi-tidal-blue #4b607c`）又跟墨色太近、读起来发灰。`#8b513c` 不是更亮的橙：饱和度
压在 pi 自己这个色相的水平上（`--pi-terracotta` 约 38%，60% 饱和的橙放在纸上比页面里
任何东西都吵），亮度取 parchment 地面（含 dashboard 压深过的那层）上作为文字还能过
4.5:1 的那一档。色淡了之后 accent 阶梯的 alpha 整体上调一档，否则染色表面会糊掉。

连带两处避让：`--danger` 保持更红更饱和的 `#9b3227`（告警是唯一该比 accent 吵的东西，
也才不会跟链接混），`--accent-amber` 推到橄榄金 `#6d5929`（否则待办行和事件行是同一片
桃色洗）。侧边栏/顶栏的 `--nav-panel-background` 横向染色也从 tidal-blue 换成同一个赤陶。

`--accent-faint → subtle → soft → fill → line → line-strong` 是官网那套「一个色相、
固定 alpha」的表面阶梯，需要染色表面时从这里取，不要新拌 `rgba()`。

### 上游新增主题与 Robin 的扩展 token

Light / Dark 保留上面的 parchment / 蓝色设计。其他 `data-theme` 调色板除了上游的
`--bg`、`--bg-panel`、`--text-*`、`--accent`，也必须覆盖 Robin 的扩展 token：
顶栏和会话侧栏共用的 `--nav-panel-background` 从当前 panel→bg 渐变，正文 `--copy`
跟随 `--text-muted`，反白文字跟随 `--accent-contrast`，强调色阶梯、焦点、选区、滚动条、
控件和纸背景都从当前语义色推导。不要让这些区域继续继承旧的蓝色或赤陶色。
这层规则集中在 `app/globals.css`，不在组件中按主题名分支；日历的分类色仍保持自己的语义。
`e2e/robin-themes.mjs` 检查所有主题实际绘制出的顶栏、侧栏及扩展 token，包含刷新、系统主题
和手机侧栏；只检查根元素的 `--bg` 不足以发现局部区域没有换色的问题。

Matrix（黑客帝国）是额外的内置深色调色板：近黑底、荧光绿强调、柔和浅绿正文，沿用同一层
Robin 扩展 token；保留告警和日历分类的语义色，不加代码雨、闪烁或全局文字发光。
入口与其他主题共用 `ThemePicker`，保存及首屏恢复由 `lib/theme.ts` 的目录自动覆盖。

Glass（玻璃）与 Dark glass（深色玻璃）现在是「跟随系统」的默认浅／深主题，主题选择器优先展示这一对；已有的手动主题选择（包括旧 Light／Dark）保持不变。`app/glass-theme.css` 在基础样式后加载，
采用用户认可的独立样板（`public/prototypes/glass/`）的薄亮边、通透中心和弯折轮廓，而非继续叠加旧的厚白框。
导航／侧栏离边 8–10px，搜索、输入框和工具栏用 38px 胶囊圆角，侧栏／设置浮层用 30px；保留浅色基底，
按用户要求复用其他主题同一套 4px／20px 工程网格（页面、Glass 外壳及 `.pi-grid-surface`），不另画纹样或引入壁纸。网格与颜色同时保留：浅色版底层保留淡蓝／淡紫边缘渐变，深色版收敛为近中性的轻微环境底色，中心保持烟黑，
仅给原网格的纸面轻微染色；不进入正文、代码或终端，不做动画。网格的七层、尺寸及十字刻度仍只有一份定义。
深色版改用基础层更暗、控件／侧栏／浮层逐渐提亮的层级，柔白文字、中性选中底色、少量浅蓝操作强调和更弱的银灰亮边；浮层为 86% 较亮灰色填充，白色背景合成仍校验 AA，遮罩 28%。
这借鉴苹果的明暗层级与克制染色，而非复刻原生 Regular／Clear；网页端不会分析背景对比度或独立翻转玻璃明暗。
两版共享清透／柔雾角色、布局及折射实现，显式选择深色玻璃不会被系统浅色偏好覆盖。
以下白色填充数值指浅色版，深色版将同一角色改用深色填充：
材质按用途分配，而非仅按尺寸：
- **清透**：搜索、Chat 输入框、短工具栏、横向导航和手机导航按钮。30% 白底、0.7px 柔化，不额外叠方向性白色蒙层。
- **柔雾**：竖向导航、侧栏、设置浮层及 ⌘K／Ctrl+K 搜索浮层。48% 白底、10px 模糊，折射强度为清透的 55%，让阅读面安静。
- 可能盖住深色编辑器／图片的浮层提高至 56% 白底并使用更深局部文字（黑底合成仍校验 AA）；12% 遮罩避免层层染灰。
  设置里的嵌入面板去掉实底，内部侧栏仅铺 12% 白色、不另加模糊。快捷搜索的原生 dialog 本体承担材质，
  内层 content 与 AssistantBar 透明，不叠实底或第二层 blur；回归用实际像素验证 top layer 能模糊背后页面。

Chromium 由 `LiquidGlassEffects` 为每个表面生成真实 SVG 背景折射：圆角距离场＋样板的平滑内弯轮廓
（`sin(πt)^0.7`，并非物理精确的 Snell 模拟）编码为 R/G 位移贴图，`feDisplacementMap` 弯折边缘后方的像素。
中心保持中性，前景文字不参与滤镜。短小清透控件采用轻微 RGB 色散；高于 120px 或面积超过 160,000px² 的输入框、
所有柔雾面板只用一次位移采样。无额外全局饱和度增益，也不运行逐帧 React 渲染。
位移贴图方案参考 [Kube](https://kube.io/blog/liquid-glass-css-svg) 与 [rdev](https://github.com/rdev/liquid-glass-react)，
独立实现，不新增库、不复制或截图整页。Safari／Firefox 保留清透／柔雾的 CSS 材质但没有位移折射，
不宣称跨浏览器全等或复刻 Apple 原生渲染器。1px 空心方向性亮边替代旧的 3px 白框；装饰层不截获指针。
首页搜索栏只在胶囊本体加滤镜，不模糊整个 sticky 宿主。Dashboard 的常驻 Chat／搜索／记录操作组（`.robin-dashboard-toolbar`）也使用清透材质，手机单排悬浮导航（`.robin-dashboard-dock`）同样使用清透；两者复用相同 CSS 和折射选择器，不强制切换用户主题。
手机首页现为「今天」：可切日期的日历与可直接完成的近期待办在同一页，不把简洁等同于拆走日历。取消包住整页的大卡片，日历／待办是并列的分组玻璃面，重要提醒在常用链接之前；首页字体按功能分层：页／分区保留衬线斜体，正文与时间改用系统 UI 字体，字重统一为 400，不再靠粗体建立层级；34px 主时间使用普通数字而非等宽斜杠零，日程标题收为 18px／1.45，15px 待办标题保留大小层级与 rem 放大。待验收采用 16px 正体标题、15px 常规列表标题和单行项目／时间元数据，说明留作读屏描述，不常驻一整行；Glass 下与日程共用柔雾底和薄亮边，不叠额外折射层，绿色标记为 8px 实心点，整条（含绿点）点击打开会话；向左滑露出右侧 Noted，点击后仅移出待验收、不删除会话。原生横向滚动吸附承担手势，纵向滚动与取消由浏览器处理，滑到底也不自动提交；Tab 可聚焦并露出同一按钮，点击区至少 44px。桌面字体不变。手机地面用 45% 主题底色减弱原网格，不改变桌面。Dashboard 首页的日历分组和桌面待办栏采用 48% 主题色＋10px CSS 背景柔化，不使用大型 SVG 位移贴图；玻璃主题内部的次要操作用强调色文字链接，收藏入口用清透填充、薄亮边、网站原 favicon／已有站点资源和浅阴影，手机与桌面共用 `SavedLinkIcon`；无可用图像时仅用中性网站图标，不再用首字或虚构 logo；安排计划是安静的文字入口，不再嵌套一层玻璃或实心灰块。手机 Glass 的滚动区铺满工作台并真正从顶栏／底栏后方通过；观察栏的 border-box 高度为内容与焦点滚动保留空间，安全区变化和键盘收起底栏也会更新。不能在滚动祖先上加 mask（会隔断背景采样）；上下栏的非交互伪元素使用 48px 渐变柔化，不用模糊掩饰硬裁切。其他正文卡片、文件编辑器、表格和列表行仍用不透明语义色，不嵌套模糊、不添加背景动画或图片请求。设置里浅／深玻璃并排占一行材质预览，放在「跟随系统」之后，不打乱其余
浅／深调色板配对。设置页本身使用透明地面、12px 外留白、30px 柔雾侧栏和分组卡片；输入与次要操作仅透色，不在内层再叠模糊。聊天的非空对话滚动面贯通顶部工具栏与底部输入区，真实内容从其后透过；只有浮层边缘做渐变柔化，滚动面不加 mask，测量后的上下内缩保证首尾文字、搜索定位和键盘焦点仍可见。无滤镜支持、减少透明度、高对比度及强制色模式降级为实底；这些无障碍偏好
也去掉背景底光。`e2e/glass-palettes.mjs` 用实际像素检查颜色和网格同时可见、两版浮层对比度与选择／刷新／降级。
`e2e/glass-theme.mjs` 检查两套设置入口、键盘、刷新、草稿、320／390／1440px、
浮层最暗背景叠色后的文字对比度与无障碍降级；另用实际输入框下的双色测试底，校验渲染像素的
透色和清透细节，并对同一条纹背景只切换各通道位移强度，证明边缘像素真的弯折、中心不动，而非仅断言 CSS
有滤镜。检查材质分工、同尺寸角色变化、尺寸变化后的贴图更新、卸载释放、主题／偏好关闭，以及 Models 嵌入面板不遮住玻璃。同时覆盖横向导航、
短屏和横屏可达性。手机抽屉离边
8px，关闭变换和拖拽投影宽度必须包含该偏移；`E2E_THEME=glass e2e/navigation-gesture.mjs` 验证
跟手、取消、再抓取及焦点返回。不据此宣称已经完成手机真机性能验证。

### 页面内 Agent 与主 Chat

笔记／Canvas、刷题、课程、产品伙伴的 `AgentPanel`，研究讨论／论文侧聊及产品实验讨论，与主 Chat 共用 `.chat-user-bubble`、`.chat-message-label`、`.chat-input-surface`、`.chat-input-textarea` 和 `.chat-input-actions`。用户消息右对齐、同款圆角浅底；助手保留连续 Markdown 阅读面和低调署名，不再使用彩色竖条卡片、像素大写署名或独立正文字号。输入框、44px 发送键、内缩及 Glass 材质从同一处继承，避免工作区通用字段样式把内层 textarea 再套框。AgentPanel 麦克风与发送并排，附件与模型入口仍可用；工具名称渐进展开，不虚构完整执行记录。页面各自的会话、权限、上传、保存及审批流程不合并。回归：`e2e/workspace-chat-style.mjs`。

工作区统一的是聊天语言，不是常驻的 Chat 外壳：笔记／Canvas、刷题和产品的桌面助手默认收起，保留文字入口；展开只显示短标题与一句上下文提示。AgentPanel 输入区分为完整文字行和操作行，模型入口取消独立字段框，与附件、语音、44px 图标发送同处一张表面；附件说明不常驻，处理进度和错误仍显示。收起不卸载已有对话；手机沿用页签／伙伴视图，不新增手势抽屉。笔记的模型菜单从玻璃输入面 portal 到 body，避免固定定位被材质改写；主 Chat 和原生弹窗保持原菜单行为。

### 跨工作区的 Glass 背景

学习中心、笔记、Obsidian、研究和产品的布局底面共用 `.robin-workspace-ground`，在 `app/glass-theme.css` 中统一透明，让 `.robin-shell` 只画一次环境色和网格。学习布局与研究布局原有的 `.pi-grid-surface` 在 Glass 下不再另画一张不透底的纸，也不重新定位环境色；笔记撤掉此前的 86% 面板色蒙层。Obsidian 仅笔记库的卡片间隙透出背景，完整阅读与图画布保留原底面；产品的页头／伙伴栏透底，产品阅读区、研究正文、资料卡、弹窗与粘性阅读头保留可读表面。产品目录、研究课题目录及共用 `WorkspaceRail` 资源导航改用 `.robin-workspace-rail` 柔雾材质（CSS blur，不生成大幅 SVG 位移贴图）；它们是阅读面的同级导航，不是正文容器。该类只标记布局，不可加到正文和浮层上；非 Glass 主题无覆盖。减少透明度／高对比度在共享背景源移除纹理，不靠各页刷白。`e2e/workspace-ground.mjs` 检查五页及其祖先链没有隐藏蒙层、共享源一致、正文不透明与 320–1440px 布局。

### 跳色：`--accent-teal` / `--accent-amber`

官网只有一个蓝，chrome 上这样是对的，但页面里每一类东西看起来就都一样了。所以额外留了
两个**刻意不进语义集**的强调色（`--accent-teal` 青、`--accent-amber` 橙，各带一个
`-soft` 表面）：它们标的是**不同种类**，不是不同状态 —— 别拿它们当 danger/warning 用，
否则一个青色 chip 会被读成告警。

现在只用在三处，"时不时"就是这个密度：

| 位置 | 色 | 为什么 |
|---|---|---|
| 日历上的**今天**（`--today-mark` / `--today-wash`） | 亮色鲜橙 / 暗色青 | 见下；亮色下它自成一个色，暗色下才等于 `--accent-teal` |
| Agenda 里的待办行、待办面板的 TODAY 分组 | 橙 | 一堆日程里一眼挑出要做的事 |
| 侧边栏"正在运行"的会话圆点 | 青 | live 信号，从那片蓝里分出来 |

两个色在深浅两套主题下作为文字都过 4:1，重新调色时保持住。

### 日历的配色与可读性规则（`components/robin/eventSurface.ts`）

用户选择 **B：按事件系列，而非日历来源上色**。自动颜色由 Google recurrence seed／本地去首尾空格的标题稳定哈希到九个槽；不再按最早开始时间排序派色，新增、删除、翻周和切视图不重排颜色。九色仍可能重复；详情中的「系列颜色」可手动覆盖或恢复自动。手选只保存在当前浏览器，同系列一起变，不写日程或 Google；本地同名事件共色，改名会改变系列身份。详见 [Calendar workspace](calendar-workspace.md)。

- **深浅表示种类**：同一组鲜明 `--calendar-*` 色，定时块用 12%、全天条用 20% 与不透明主题面板混合；日／周／议程一致，月视图定时事件用同色圆点。
- **左侧竖线表示系列**：3px 实色，不拿颜色或透明度暗示可编辑性；来源和只读限制保留文字说明。共享的 `--event-*` 不改，Todo／Product／Learning 配色不受影响。
- **Apple 风格层级**：日历局部用系统字体、日期半粗、时间用对齐数字、分组 44px 工具栏、蓝色新建操作、红色今天圆标与当前时间线、柔和网格；不加大面积模糊或新动画。
- **文字层级固定**：标题半粗，时间小号，足够高的卡片再显示地点；标题按卡片高度
  显示一到两行，而不是无条件截成一行。
- **完整一天而不压缩字号**：手机默认议程＋日期条（有已保存视图时保留），桌面默认周视图；手动选择分别记在手机与桌面偏好中，URL 显式指定的视图优先。日/周视图每小时 56px，展开 06:00–21:00，不再用 680px 的内层窗口截断；垂直随 Dashboard 页面滚动，窄屏只在日历内部横向滚动。全天和跨天事件留在顶部条带；大量全天事项的条带单独限高滚动。拖动到屏幕边缘时滚动 Dashboard，预览不覆盖页面顶栏。跨越显示边界的定时事件裁剪显示，时段外的日程仍保留，可从议程或月视图查看。
- **日/周待办渐进展示**：周视图用固定 60px 的任务预览行替代「待办 N 项」：优先显示当天到期任务的两行标题，其余以 `+N` 提示，空日期留白，点击打开当天完整列表；日视图的日期列与连续多日跨度保留，最多展示三条轨道，隐藏任务按覆盖日期计入「还有 N 项」；连续跨度优先，不承诺填满每一天的三个位置。中性底与轻分隔取代虚线彩框，勾选和两行标题同行，今天／逾期强调状态，手选颜色仅保留小色点。整个条带可折叠。桌面次要操作在精细指针 hover／键盘聚焦时显现，不挤占平时标题空间；触屏操作常显且至少 44px。被截断的标题继续通过「…」、停留 220ms 或聚焦打开原生 Popover 全文预览，原有关闭方式与轻量动效保留。手机（≤640px）点击两行标题打开当天完整列表，不注册 hover 或渲染 Popover；从桌面缩到手机时移除已开的预览。完整列表用原生 modal，保留全文链接、日期范围、完成和改期，错误留在列表内、关闭恢复焦点；不修改待办内容或新增轮询。详见 [Calendar workspace](calendar-workspace.md)。
- **Hover 的边界**：用于补充全文、解释图标、提供轻量反馈；必须有键盘与点击等价入口，不隐藏必需操作，不触发保存，通常不改变列表行列尺寸；Todo 侧栏按用户要求允许行高平滑展开全文，但不改变列宽。优先处理信息被截断的位置，而不是给每块内容都加弹层。
- **待办拖拽改期**：日历各视图和右侧 Todo 都使用独立把手，避免劫持链接、勾选与手机滚动；点击把手打开日期编辑器，支持键盘。拖入日期后修改 `due`，不创建日程，不改 `plannedOn` 或估时；DDL 仍只精确到日期。日历多日条保留抓取日期偏移，侧栏多日任务把截止日放到目标日期，两者都保留跨度。PATCH 带 API 返回的任务 `revision`，并发修改或删除不覆盖；写入确认后更新缓存，失败保留原日期和编辑草稿。

定时事件采用 8px 控件圆角、全天条 4px 细节圆角；网格仍为直线，不用圆角改变时间长度或重叠布局。`e2e/calendar-design.mjs` 检查跨日期窗口稳定性、手选／恢复／跨标签页／存储失败、九色与文字对比度，以及深浅主题和 320px 手机选择器。

### 今天：`--today-mark` / `--today-wash`

以下为历史全局配色基线；日历现已在 CSS module 内覆盖为红色圆形日期标记与当前时间线，日期列仅轻微中性强调，不再整列染成事件色。其他区域的 token 未随这次日历改动调整。

这个色只留给今天，别处不用。**两套主题拉开的维度不同**：暗色 accent 是蓝，今天靠色相拉开
——走青（`--accent-teal`）；亮色 accent 是低饱和赤陶，今天靠饱和度拉开 —— 同一个橙色家族
但饱和度是它的两倍多（`#b34a12`），整页哑光陶土里唯一鲜的一块。`#b34a12` 已经是这个色相
在"日期块上反白的 `--on-accent` 还能过 4.5:1"前提下最鲜的一档；`--today-wash` 的 alpha
也比 `--accent-soft` 高，格子才比里面的事件块亮。组件里一律只认 `--today-mark`，不要写死
其中任何一个。

今天在三个视图里是同一套：实心底反白的日期块（`.pi-today-badge`）、整格/整列的
`--today-wash` 洗色（比 mark 更浅更粉，才压得住底下的事件块）、以及月视图里
`border + inset box-shadow` 叠出来的双层框（用内阴影而不是 2px 边框，格子才不会在细线
网格里错位）。周视图的当前时间线、月视图当前周的左侧竖线也走 `--today-mark`。

### Product 的配色（`components/robin/productSurface.ts`）

沿用日历那条规则 —— **颜色是边，不是填充**：一行保留面板自己的底，色相走左侧 4px 竖脊，
扫下来是一条色脊而不是若干块互相打架的洗色。

调色板直接复用日历那九个色槽（想法和日历事件永远不同屏），但**按名字取色的地方必须自己在
两套主题里都验一遍** —— 日历不用管这件事，它是按顺序发牌，从不点名。最要紧的一条：
**teal 槽不能用**（亮色 `#5c8a83`，暗色 `#9488cc`，因为暗色下 today 占了青），暗色里它会
贴到 iris 上。

三个状态里只有两个上色：`thinking → slate`、`making → fern`，**parked 保持中性**。颜色在
这里编码的是"这件事还活着没有"，把第三个也涂了等于只说了"有三个状态"——那是三个词已经说过
的事。fern 贴近 `--success` 是有意的：在做的东西就是在往成里走。

Library 的五个 category 各取一个色槽做 chip，只是五个彼此分得开的颜色，不再影射任何流程——
流程已经没有了。状态色（`--success` / `--danger` / `--accent`）只留给真正的状态，默认态不上色。

这些约束有测试兜底：`extension/robin/product-domain.test.mjs` 与 `components/robin/*.test.mjs`。

### Dashboard 的纸感：`--dashboard-ground` / `--card-shadow`

聊天是一整份连续文档，保持官网那种平的半透明面板；dashboard 是几张分开的纸，所以地面用
`--dashboard-ground` 往 parchment 压一档（半透明，网格仍透得出来），`.pi-card` 反过来
改成**不透明** `--bg-panel` + 一层很淡的 `--card-shadow`。没有这一步两者会糊在一起。

侧边栏和顶栏的背景走 pi 的 `--nav-panel-background`：竖向暖白→纸色渐变上，叠一层
横向的 honey `#eacd7c` → tidal-blue 的染色洗。这是亮色主题里唯一的暖色，去掉后整页
只有冷墨+冷纸，所以保留（对应 `--pi-honey`）。

### 工具工作区的鲜明配色例外

按用户明确要求，工具**目录及内页**不沿用低饱和强调色：音视频及录音转写用鲜橙，图片／文档用紫色，文字／数据用蓝色，Mac 监控用青绿。颜色仅在对应 CSS module 的工具作用域定义，分别提供亮／暗色的实心按钮与文字配对，不改全局主题。目录与内页共用分类色；目录为 24px 页头／搜索面和 16px 工具卡片，配实心图标底、3px 彩色顶边与分组短色标。悬停／按下只强调边线，不移动卡片，键盘焦点环保持可见。标题图标、上传边界、分区短标记、主按钮和结果边框使用这些颜色；正文、面板、阴影、错误／警告仍复用语义 token，不让颜色成为唯一说明。

输入／选项／结果、录音的采集／文字稿／设置、Mac 的监控／磁盘／目录／缓存是独立 16px 卡片；控件 8px，Mac 确认框 24px。不为圆角添加裁切共享容器的 overflow，不新增动画、依赖或轮询。`e2e/toolbox.mjs` 检查所有 11 个转换工具的实际圆角、明暗主题主操作饱和度与文字对比度；`e2e/recordings.mjs` 和 `e2e/mac-workspace.mjs` 覆盖独立工作区及交互回归。

### 圆角层级：柔和表面，精确网格

| Token | CSS px | 用途 |
|---|---:|---|
| `--detail-radius` | 4 | 行内代码、小标签与紧凑细节 |
| `--control-radius` | 8 | 按钮、输入字段、代码块、工具执行框 |
| `--card-radius` | 16 | 独立卡片、Dashboard 右栏、Chat 输入区与用户消息、Research 阅读面 |
| `--panel-radius` | 24 | 独立大型浮层，如日程编辑、命令面板、论文阅读弹窗 |
| `--pill-radius` | 999 | 明确需要胶囊的元素；头像和状态点仍为 50% |

所有主题共用形状；第一轮仅替换圆角，后续按组件用途调整间距与层级，不能用圆角 token 代替布局设计。Tailwind 旧尺寸映射到同一层级：
默认/xs/sm → detail，md/lg → control，xl/2xl → card，3xl/4xl → panel。
新代码优先使用语义名称；`.pi-panel` 被原生字段或按钮使用时取 control，不把字段变成卡片。

贴边侧栏、工具栏单元格、时间网格和表格仍为直角；连续阅读正文不再套卡片。
分段控件只圆外侧两端，内部分隔线保持直线。全屏移动阅读面保持 0，不能让圆角露出背后页面。
不在共享卡片上添加 `overflow: hidden` 来实现圆角：它会裁掉菜单和焦点环、破坏 sticky；
有独立滚动语义的容器保留自己的 overflow。紧贴外框的着色子面需要继承圆角。
真正等距嵌套才用 `max(0, 外圆角 − 边框 − 内缩)`；独立控件不是外框的等距轮廓，
无需假装同心。既有局部控件的 5–12px 圆角暂不批量替换。

输入框里的操作不能沿用直角时的贴边位置：Chat 与首页搜索／执行框采用 8px 操作内缩，
麦克风、发送、Steer／Follow-up 统一 44px 高并对齐。局部 `--input-action-radius` 按外框
减去内缩与边框计算（最低取 control radius），玻璃主题的 28px 外框同步带动内层弧度。
Chat 在窄栏自动换行，手机生成中把操作放在文字区下方，不压缩可编辑宽度；紧凑侧聊保持
无外框。只调整这些复合输入框，不给普通字段／工具栏全局加 padding，也不用 overflow
裁切焦点环。回归：`e2e/input-action-insets.mjs`。

### 交互反馈与动态效果预算

- `.ui-action` 按下只即时改变底色，不缩放整行、不动画化尺寸或阴影；禁用态不响应，语义文字色与焦点环保留。松开沿用原有短颜色过渡。括号展开仅在精细鼠标、可悬停且未要求减少动态效果时启用（140ms）；键盘焦点不移动括号。
- 日历 Todo 的鼠标全文预览用原生 Popover 的 `@starting-style`＋离散 `display/overlay` 过渡：180ms 淡入并从 0.97 缩放，140ms 沿原路径收起，缩放原点指向任务（向上展开时取底边）。仅变换与透明度参与动画，不改变日期列布局；关闭时立即停止命中，快速反向可从当前值继续。键盘／显式点击保持即时，reduced-motion 仅保留 120ms 淡入淡出；旧浏览器降级为即时展示。练习热力格的 hover 同样用 180ms 过渡，仅精细鼠标且无 reduced-motion 时缩放。`e2e/todo-calendar-drag.mjs` 检查实际入场／退场中间帧、减少动态效果、键盘与手机回归。
- Shell 的 reduced-motion 覆盖必须放在全部响应式规则之后，覆盖导航、左右面板和遮罩；只取消 transition，不清除用于隐藏关闭抽屉的 transform。Robin 手机抽屉只在标题把手支持跟手横拖、速度投影与可打断回弹，不抢列表纵向滚动或浏览器边缘返回；键盘和 reduced-motion 松手直接落位。设置保存成功不弹跳、不画阴影。高对比度偏好提高语义文字与边界，减少透明度偏好改用不透明纸面，不为了适配而新增玻璃效果。
- Todo 侧栏长标题悬停时在原行展开，不是日历浮层：`TodoPanel.module.css` 用 200ms `ease` 的 Grid 行过渡撑开／收回，全文保持换行以免收回时跳高；单行省略副本只负责视觉、`aria-hidden` 且不截获点击，真实标题链接与可访问名称始终唯一。键盘焦点即时展开，手机／粗指针直接显示全文，reduced-motion 不动画。`e2e/todo-row-motion.mjs` 验证实际行高和后续行位置的中间帧、收回／反向、短标题、链接和手机全文。
- Todo 完成/重新打开只在该行显示静态「保存中」并禁用复选框，同步 ref 防止 React 提交前的重复激活；服务端确认并刷新后才改变勾选状态，失败保留原状态和错误提示。不加 spinner、离场动画或逐帧 React 更新。新增任务另有提交锁，不用全表 working 状态驱动每一行的等待反馈。
- 新信息的邮箱／AI 周报／播客选择器保持紧凑，不加切换动效；手机隐藏重复页名，三个入口同排且至少 44px 高。各来源首次访问才挂载，访问后保留状态，隐藏时停止来源轮询；全局导航徽标仍按原规则更新。活动日期筛选移交焦点到列表标题，键盘或 reduced-motion 使用即时滚动；活动／播客图片缩放仅允许精细鼠标悬停。活动保存、扫描与播客摘要／刷新使用同步提交锁，等待反馈不新增常驻动画。
- 回归：`e2e/interaction-feedback.mjs` 模拟全部 API，检查慢请求、重复勾选/提交、失败重试、重新打开、按下几何不变、键盘焦点及 320–1440px reduced-motion；以 80 条待办和 4× CPU 降速记录反馈延迟。它不是低端手机 GPU 测试，也不代表整个应用的帧率保证。
