# Notes Canvas implementation

## Context
At `3f5a9c7a721043c315a7426dd96f321c9c99b345`, `components/robin/NotesWorkspace.tsx` owns draft selection, URL state, the Notion tree and the right-side Agent. `extension/robin/notes-domain.ts` persists notes using `paths.ts`'s locked atomic writes. `app/api/robin/notes-agent/route.ts` accepts a per-document snapshot and scopes conversations by draft ID. User behavior is specified in PRODUCT.md.

## Proposed changes
- Embed MIT-licensed Excalidraw (React 19 compatible) through a client-only dynamic import. It owns drawing geometry, bindings, selection, clipboard, history and image serialization; do not implement a second drawing engine.
- Override the editor's theme tokens and default drawing style (sharp corners, non-rough lines), preserving native editor controls. Self-host its font assets via a small preparation script used by postinstall.
- `canvas-font.ts` adapts Excalidraw 0.18.1's exported font-name table: its existing local-font slot (2) resolves to the computed `--font-serif` stack. Keep the internal `Helvetica` property readable but non-enumerable so the renderer's name lookup uses Notes typography while its existing metadata remains intact. Canvas measurement, editing and SVG export then share the same stack; a textarea-only CSS override would not. Restore saved element dimensions against that stack, and preserve explicitly selected alternative font IDs. Native `.excalidraw` files retain numeric IDs, so other hosts can use their own typography for slot 2.
- Add a Canvas domain with one JSON file per board under Robin's data directory. Domain functions own ID/title/scene validation, size bounds, revision conflicts, locked writes and deletion. List responses contain metadata only. No routes access the store directly.
- `/api/robin/canvases`: GET summaries or a single ID; POST create; PATCH save a title+scene against a revision; DELETE by ID/revision. Bound incoming JSON before parsing, and distinguish missing boards from conflicts.
- `/api/robin/canvases/library` GET/PUT adapts the same Canvas domain's shared `canvas-library.json` document. Validate item IDs/status/elements and total size, then save under a file lock with a revision check. Load it before mounting the editor; a load failure must not become an empty library. `useHandleLibrary` owns official URL validation, import merging and user confirmation, while `libraryReturnUrl` carries `?canvas=ID` back from the public catalog. `onLibraryChange` uses the existing save queue (now typed for either scenes or library items), not the native persistence adapter: retain the complete pending library on errors, expose Retry, and flush both queues before navigation. The native adapter's incremental updates would otherwise lose an earlier failed import on a subsequent change. Library and canvas conflicts require explicit reload/export, never blind overwrite.
- Persist only live drawing elements, their referenced image files and a small viewport state. Deleted elements and unused image bytes remain available in the editor's undo history but are reclaimed on disk. Do not serialize transient selection, collaborators, menus or editor objects. Reject embedded web pages and non-image asset URLs.
- A small testable save queue coalesces changes and serializes requests. It advances revisions only on acknowledged saves and retains newer edits while requests are in flight. Failed saves remain pending; conflicts require explicit reload, not blind retry.
- Canvas workspace exposes a flush operation and its acknowledged revision to Notes selection handlers. Flush before changing documents; deletion uses that revision (or the listed revision), never silently adopts another tab's changes. Warn before unload, and intercept ordinary navigation links while edits are pending. Keep the canvas mounted when changing mobile panes.
- The library is a separate component sharing Notes' existing draft-list styling. Canvas selection uses `?canvas=ID`, mutually exclusive with note selection. It does not merge canvas storage with Markdown drafts or Notion.
- Reuse Notes' model selection and AgentPanel. Send a bounded textual scene snapshot with `documentKind=canvas` and a namespaced conversation ID; adjust the chat preamble accordingly. Insert replies only through an explicit sticky-note action.

## Testing and validation
- Domain tests: independent create/read/update/delete, metadata-only lists, atomic revision conflict, missing/deleted board writes, invalid IDs, malformed elements, invalid assets and oversized scenes (PRODUCT 1, 4–6).
- Save queue tests: rapid edits, edit during in-flight save, retry after transport failure, conflict retention (4–6).
- Browser test using an existing dev server and mocked board APIs: create/rename two boards, sticky note editing, drawing, undo/redo, switch/reload persistence including an image, deletion cancellation, autosave failure/conflict, mobile tabs and desktop column geometry (1–10).
- The browser test also round-trips its real editor-generated scene and image bytes through the actual domain in a temporary data directory. It checks the actual Canvas 2D font, editable-text font and a downloaded SVG's font stack. API tests exercise 400/403/404/409/413/415 responses and metadata-only lists.
- Library API tests cover persistence, board-deletion independence, empty-library saves, stale revisions and untrusted/oversized requests. Browser tests follow both a fresh catalog return URL and an in-page import, insert assets, export backups, remove assets, switch boards/reload, and exercise failed and conflicting library saves. Editor-produced library items also round-trip through the real domain in a temporary directory.
- Run existing Notes layout tests, focused domain/component tests, TypeScript and lint. Visually inspect English/Chinese and light/dark layouts. No `next build` against the development checkout.
- Excalidraw pins old transitive nanoid/Sass versions; narrow package overrides select patched versions without updating unrelated application dependencies. The upstream Mermaid dependency chain still has low-severity audit findings.
