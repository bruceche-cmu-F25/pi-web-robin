# Twice-daily complete mail review

Original approved scope: review received mail bodies, notify about attachments by name only; never open attachments. Use the existing phone-push channel at 08:00 and 18:00 America/Los_Angeles. The default mail-only lane replaces the legacy mail digest, not calendar reminders, jobs, weekly or the separate daily agenda. With the separate `ROBIN_BRIEF_MORNING_DAILY=1` gate on BOTH processes, the morning edition also collects calendar, open deadlines and fixed public feeds and replaces the old agenda; the evening remains mail-only. This new gate is not automatically enabled on existing installations.

1. At each boundary, enumerate every received message in its fixed interval, including read, archived, promotions and social mail. Exclude spam, trash, sent and drafts. Every new morning/evening interval starts at least 48 hours before its boundary, including the first run and DST transitions. An older unreported interval extends that start further back. Successful delivery never shortens the 48-hour lookback; overlapping bodies reuse cached reviews. Already-started intervals and published editions stay immutable.
2. Fetch and review every available body, not snippets or an eight-mail sample. Batches bound individual calls; completed batches survive retries. Long bodies are split without discarding the tail. MIME attachment filenames are reported deterministically, not inferred by the model. No attachment bytes are decoded or attachment-download endpoints called. Unavailable/external/encrypted bodies are explicitly failed, never counted reviewed.
3. Model input is untrusted data, with zero tools and no automatic mail/task/event mutations. Every supplied fragment must receive a validated result with an exact source quote. Uncertain paid calls are not automatically repeated. Known malformed completed responses become explicit review failures, not silently successful reviews.
4. The report states the exact interval, received/reviewed/failed counts and attachment notices. Full review does not promise semantic accuracy. All reviewed mail summaries remain available in the reader; priority selection does not stand in for full review.
5. Empty intervals still produce a concise scheduled mail notification. Transient provider failures retain progress and retry later. No successful-looking report is sent before enumeration/processing finishes. A hard guard or interruption must not be described as all-clear.
6. Each date/time owns a different immutable edition and delivery receipt. Retries reuse the edition, preserve conservative delivery uncertainty, and cannot replay the old daily mail notification. Old Brief editions and manual previews remain unchanged. An expired morning slot is not sent alongside an evening slot; evening collection carries unreported coverage forward.
7. The existing supervised bridge owns the clock. Reading pages does not perform acquisition, start models or send. Schedule activation has an explicit first boundary; no immediate out-of-schedule test notification is implied. Push service acceptance still requires separate real-phone confirmation.

## Implementation / validation

Reuse Brief SQLite leases, checkpoints, immutable evidence, editions/outbox and the existing push transport. Store window manifests and per-batch reservations/results in the existing source-state table; no new database or schema migration. Yield between bounded network/model batches so bridge requests remain bounded. Add two delivery slot identities without rewriting old ones. Verify DST boundaries, pagination/restarts, full-body tails, promotion inclusion, attachment exclusion, model output completeness, uncertain-call fencing, two independent receipts, calendar-lane independence and read-only reader behavior before activation.
